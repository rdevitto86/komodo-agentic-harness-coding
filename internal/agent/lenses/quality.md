# quality

## quality.1

Names say what the thing is or does. The name of a function, type or variable describes its purpose. A vague, empty or misleading name is a finding. Quote the line that declares it.

## quality.2

The same code is not written twice. A repeated block is shared. Quote the first line of the second copy.

## quality.3

Comments follow the comments standard of the brief. A function, public or private, carries a comment of at most 3 lines that says what it does and never restates its name. A type, constant, variable or field carries a comment of at most 1 line. Test files and test helpers may go without. A loop of 16 lines or more, and a named function literal of 5 lines or more, carry a one-line comment above. A comment never opens with a label such as WHY, never names a plan, task, ticket, phase or version, and a comment the author did not write is never removed or rewritten. Quote the function or field that lacks the comment or breaks the standard.
